03 / YOUR DAILY ROUTINE

Two trackers.
One place to return to.

Start with a Google sign-in. Your habit spreadsheet is found or created automatically.

▦

Habits

Add a habit with the + button. Use a checkmark for yes/no habits or a number for things you measure. Record a value in the calendar grid and move between days.

Tap and hold a name on your phone, or click it on a computer, to rename or delete it. Renaming preserves its history. Deleting a habit removes its whole column across all days after confirmation.

↗

Workouts

Open Workouts and choose a day. Add an exercise or reuse an existing name. Upraviť série opens the set editor: enter repetitions and weight in kilograms.

The editor grows an empty row as you type. Save all sets together. Removing an exercise from one day keeps its history on other days. The workout spreadsheet is created on your first online visit to this tab.

Make it yours

Open the gear icon for Nastavenia. Choose light, dark, or system appearance; create or connect separate spreadsheets; inspect pending changes and download a JSON backup.

  3. If shown, keep Open as Web App enabled, then tap Add.
  4. Launch from the new icon and sign in to Google.
ANDROID

Chrome → Install app

  1. Open the tracker in Chrome over HTTPS.
  2. Use Nainštalovať aplikáciu when the tracker offers it.
  3. Or open Chrome’s ⋮ menu and choose Install app or Add to Home screen.
  4. Confirm and launch from the app icon.

Before going offline: sign in and load each tracker you want to use. Wait for the first online visit to finish. The installed app may have separate storage from your browser, especially on iOS, so load your records inside the installed app too.

Desktop Chrome and Edge also offer installation from the address bar or browser menu. Installation wording varies by browser and OS.

05 / CONNECT YOUR OWN GOOGLE PROJECT

Your account.
Your spreadsheets.

For a self-hosted copy, configure Google once before signing in.

  1. Enable the APIs

    Create or choose a Google Cloud project. Enable Google Sheets API and Google Drive API. Configure the OAuth consent screen and add your account as a test user if the app is in Testing.

  2. Create a Web application OAuth client

    Add http://localhost:5173 for development and your production origin, such as https://fokot.github.io, to Authorized JavaScript origins. Origins have no path. The app uses popup authorization.

  3. Set the public client ID

    Locally, copy .env.example to .env.local and set VITE_GOOGLE_CLIENT_ID. On GitHub, add the same name as an Actions repository variable before deploying. No client secret belongs in the app.

Which files can the tracker access?

The app requests openid email profile and drive.file. It can work with files it creates or files explicitly opened with it. Pasting an arbitrary Drive URL does not grant access.

Settings can create a spreadsheet, select files already accessible to the app, or use the optional Google Picker. Configure VITE_GOOGLE_PICKER_API_KEY and VITE_GOOGLE_PROJECT_NUMBER from the same Google project to enable the full Picker. See the README for API-key restrictions.

Keep the same Google Cloud project when moving your deployment if you want to retain existing file grants.

GitHub Actions takes it from here

  1. In Settings → Pages, choose GitHub Actions as the source.
  2. Add VITE_GOOGLE_CLIENT_ID under Settings → Secrets and variables → Actions → Variables. Add optional Picker variables if you use it.
  3. Add your HTTPS origin to the Google OAuth client and update Picker referrers if configured.
  4. Push to main, or run Deploy app and documentation from Actions. The workflow tests, builds, and publishes dist/.

The workflow gets the path from GitHub Pages. The manifest, icons, links, and service worker all stay inside that path.

02 / ON YOUR DEVICE

03 / IN YOUR ACCOUNT

Google Sheets

Queued edits sync while the app is open and authorized. Each date is a row; habits and exercises are columns.

The service worker keeps the app available

It precaches the built HTML, scripts, styles, manifest, and icons. Google API responses and tokens never enter this cache. It only handles known static assets inside the deployment path.

Updates wait for a natural pause

A new version downloads in the background. Save your drafts and close all tracker windows and tabs, then reopen to use it. Updates do not force a reload while you are editing.

Spreadsheet layout and concurrency

The habits file contains Habits and HabitDefinitions. The workouts file contains Workouts and WorkoutDefinitions. Sheetbase’s hidden _Sheetbase tab stores synchronization receipts.

Normal writes change only touched cells. Structural edits preserve stable habit or exercise IDs. Unrelated tabs stay intact. Duplicate date keys or incompatible headers stop synchronization and retain pending edits.

Different devices can edit the same cell. The last successful synchronization wins; Google Sheets does not provide a distributed transaction across devices. Use refresh to fetch direct spreadsheet edits.

08 / GOOD TO KNOW

A few honest
answers.

Can I use it completely offline?

After an online sign-in and initial load, you can reopen the cached app and edit already loaded records. First-time sign-in, loading a new spreadsheet, and uploading changes need internet. If you signed out, sign in online again to restore your active account.

Will changes upload while the app is closed?

Do not rely on it. Synchronization runs while the app is open or when you reopen it with a connection and valid Google authorization. An expired Google session pauses uploads without blocking local edits.

Where are my records and credentials stored?

Loaded records and pending edits are in IndexedDB. The active profile and file choices are in local storage. OAuth access tokens are held in memory only. Your synchronized history is in your Google Sheets.

Clearing site data, private browsing cleanup, or browser storage eviction can remove unsynchronized changes. Use the JSON backup in Settings before clearing storage or moving hosts. Paths on the same origin share browser storage; separate devices, browsers, and origins do not.

Why is the Install button missing?

The button appears when the browser offers an installation prompt. On iPhone, use Safari’s Share menu. On Android, use Chrome’s menu. Check that you opened the app over HTTPS and that it is not already installed. The local development server deliberately does not register the offline worker; test a production build instead.

What if sign-in or synchronization fails?

Check your connection and Google authorization first. For an origin error, add the exact HTTPS origin to your OAuth client without a path. For inaccessible files, use the same Google project and select a file granted to this app. For a schema conflict, keep your pending edits, download a backup, and correct duplicate dates or incompatible managed headers before retrying.
